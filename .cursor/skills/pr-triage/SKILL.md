# pr-triage

自動レビューの続きだけを行う。`review-*` の8観点はやり直さない。コードは変更しない。直すと判断した指摘の実装は実装段が行い、`@ai-review /apply` は実行しない。

開いている段の完了・境界・この段ですることが、このスキルより優先する。

## 入力

- `.cursor/playbook/project.md` の `github.review_workflow` と `test.command`
- 対象 PR の投稿済みレビュー本文とインラインコメント（`gh` で取る）
- その PR の差分

`github.review_workflow` は指摘の出所を示す。ワークフローファイルを実行手順としては読まない。対象 PR が指定されていなければ、番号を確認してから進む。

## 手順

1. 投稿済みの自動レビューを読む。投稿が無ければ、無いと返して終わる。
2. 各指摘を差分と突き合わせ、直すものと見送るものに分ける。見送るものには理由を1文添える。
3. 直すと判断した指摘と、差分が変える振る舞いから、動作確認する項目を出す。`test.command` が空でなければ、そのコマンドを実行手段として添える。
4. この PR の対象外で、付随するバグや新しい課題が見えたときは、行を作らずに列挙し、「起票必要ですか？」と聞く。見えなければ聞かない。起票はしない。
5. 結果を会話に返す。

`review-test-quality` が見る「差分の中にテストがあるか」は、ここでは判断しない。

## 出力

- 直す
- 見送る（理由1文）
- 動作確認項目
- 起票の確認（見えたときだけ。質問は「起票必要ですか？」）
