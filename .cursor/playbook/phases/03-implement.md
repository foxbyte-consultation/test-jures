# 実装

## 完了

変更が `rules.entry` の規約に沿っている。成果の区切りでは、`github.pr_template` の見出しのまま PR がある。

## この段ですること

1. 下の「main」を先に済ませる。承諾されたら、最新の `main` から、質問した名前のブランチを切ってから変える。
2. 対象の1件があるときは、その URL を着手の返事に書く。ステータスを変えるのは、着手するときと PR を出したときの2回だけである。
3. `rules.entry` に従って変える。層や画面の規約は、この段に再定義しない。
4. 画面を触らない変更では `repos.paired` を開かない。
5. 成果の区切りで PR を作る。参考にした Notion の URL は「やったこと」に書く。見出しは増やさない。開いていないページは足さない。作り方の質問だけでは PR を作らない。

## 境界

PR の体裁は `.cursor/rules/pull-request.mdc` が正であり、ここには繰り返さない。タスクの起票と設計書は作らない。

スキルが無いときは、この段の「この段ですること」だけで進む。

## main

着手の前に `main` を見る。すでに同じなら聞かない。差分が、今回触るファイルと重ならず、振る舞いを変えない小さな更新だけなら聞かない。それ以外は内容を短く示してから、次を聞く。ブランチ名は、このリポジトリの既存の `feature/` の付け方に合わせ、質問の中に具体名を入れる。承諾の前に pull も branch も切らない。作業ツリーにある別の変更は、混ぜない。捨てない。

mainでPULLできる内容が{内容}です。最新化して `{ブランチ名}` を切ってもよろしいですか？

承諾されたら、`main` を最新にしてから、その名前のブランチを `main` から切る。古いブランチへ `main` を混ぜて続けない。

## 開くスキル

手順スキルは無い。`rules.entry`（`.cursor/rules/`）を開く。PR を作るときは `pull-request.mdc` と `github.pr_template` を使う。
