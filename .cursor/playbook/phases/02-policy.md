# タスク方針

## 完了

`docs/detailed-design/` に、対象タスクの設計書がある。読んだ Notion の URL が、タイトルの直下にある。

## この段ですること

1. 下の「main」を先に済ませる。
2. 対象の1件を読む。その URL を、着手の返事と、設計書のタイトル直下に書く。開いていないページは足さない。
3. コードと `rules.entry` で検証してから設計する。入力のファイルパスや原因は、そのまま採用しない。
4. 自分で決めてよいことと、確認が必要なことを分ける。確認事項は設計書の先頭に置く。
5. 画面を触るタスクのときだけ `repos.paired` を開く。開かないときは、画面側のファイルを推測で書かない。

## 境界

切り出しが書いた見出し「方針」の2〜4文は書き換えない。`docs/features/*/plan.md` は作らない・書き換えない。実装はしない。

設計書の全文は Notion へ転記しない。書き戻すのは、そのタスクに残すと決めた確認事項だけである。

スキルが無いときは、この段の「この段ですること」だけで進む。スキルを開いても、完了・境界・この段ですることはスキルより優先する。

## main

着手の前に `main` を見る。すでに同じなら聞かない。差分が、今回触るファイルと重ならず、振る舞いを変えない小さな更新だけなら聞かない。それ以外は内容を短く示してから、次を聞く。承諾の前に pull しない。作業ツリーにある別の変更は、混ぜない。捨てない。

mainでPULLできる内容が{内容}です。最新化しますか？
