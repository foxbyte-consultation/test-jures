# レビュー確認

## 完了

投稿済みの自動レビューが、直すものと見送るものに分かれ、動作確認の項目がある。対象外のバグや新しい課題が見えたときは、起票するかを聞いている。投稿が無ければ、無いと返して終わっている。

## この段ですること

1. 対象 PR の投稿済みレビュー本文とインラインコメントを `gh` で読む。投稿が無ければ、無いと返して終わる。
2. 各指摘を、その PR の差分と突き合わせる。直すものと見送るものに分ける。見送るものには理由を1文添える。
3. 直すと判断した指摘と、差分が変える振る舞いから、動作確認する項目を出す。`test.command` が空でなければ、そのコマンドを実行手段として添える。差分の中にテストがあるかは、ここでは判断しない。
4. ローカルの見立てと Actions の投稿が食い違ったら、Actions の投稿に従う。
5. この PR の対象外で、付随するバグや新しい課題が見えたときは、行を作らずに列挙し、「起票必要ですか？」と聞く。見えなければ聞かない。
6. Notion に書くのは、そのタスクに残す製品判断だけである。レビュー指摘の一覧も、起票前の課題も書かない。参照したページの URL は、返事に一度書く。

## 境界

`review-*` は開かない。コードは変更しない。直すと判断した指摘の実装は実装段が行う。`@ai-review /apply` は実行しない。起票はしない。起票すると決まったあとは切り出しが行う。

スキルが無いときは、この段の「この段ですること」だけで進む。スキルを開いても、完了・境界・この段ですることはスキルより優先する。
